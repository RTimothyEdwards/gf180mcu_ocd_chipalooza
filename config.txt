#--------------------------------------------------------------------------------------
# config.txt:  Project and I/O configuration for the Chipalooza Harness
#
# Editable fields:
#
# 1. "project_id" is the chip ID number, an arbitrary string of 8 hex
#    digits.  This value applies for the entire chip, appears in the
#    corner of the chip on the top layer metal, and can be read back
#    from the SPI.  This value should be unique for each tapeout.
#
# 2. The "s[x]_source" for [x] = 1 to 18 are the URLs for the user
#    projects and are used to automatically clone the user repositories
#    into submodules, check them, and integrate	them into the chip top
#    level.
#
# 3. The "s[x]_version" for [x] = 1 to 18 provides the branch and the
#    commit hash to use for each project.  The commit is what freezes a
#    project for tapeout.  Either field may be given as "-":  a branch
#    of "-" means the remote's own default branch (these are eighteen
#    independent repositories, and not all of them call it "main"), and
#    a commit of "-" means to take the tip of that branch, in which case
#    scripts/get_projects.sh records the hash it checked out here.  An
#    existing hash is never overwritten;  edit it yourself to move a
#    project, then run "make projects-update".
#
#    Note that prior to tapeout of the harness chip, all projects
#    should be marked with a valid commit so that the state of the
#    whole chip at tapeout is frozen.
#
# 4. The "slot_[x]" entry is unused by any script but assigns slots to
#    users by name for the convenience of remembering whose design is
#    associated with which slot.
#
# 5. The "s[x]_an[[y]]" entry allows users to specify that individual
#    dedicated pads connected to the corresponding user project should
#    be a specific pad type.  Changes may *only* be made in coordination
#    with the slot's project designer, as changes modify a number of
#    cell views, including the project wrapper and its pinout, the
#    padframe and its pinout, and the harness chip core and its pinout.
#    See the README and the Makefile options for how to rebuild the
#    entire chip after a project pad has been changed.  (By contrast,
#    barring pad changes, a user project is simply dropped into the chip
#    top level and requires no additional changes.)
#    Note:  [x] is the slot number and [y] is the pad count for the
#    slot.  Different slot numbers have different numbers of dedicated
#    pads.
#    
#    The "s[x]_an[[y]]" entry has two fields:
#
#    A. The "pad type" is one of 6 valid pad types:
#		gf180mcu_ocd_io__bi_24t
#		gf180mcu_ocd_io__bi_t
#		gf180mcu_ocd_io__bi_a
#		gf180mcu_ocd_io__in_c
#		gf180mcu_ocd_io__in_s
#		gf180mcu_ocd_io__asig_5p0
#
#	The default value of each user project pad type is an analog
#	pad gf180mcu_ocd_io__asig_5p0.
#
#    B. The "core signal name" is an arbitrary name for the core signal
#	(root name) at each pin.
#
# Do *not* change the key values (e.g., "project_id" or "s*_an[x]"), which are
# parsed by various scripts.
#--------------------------------------------------------------------------------------
